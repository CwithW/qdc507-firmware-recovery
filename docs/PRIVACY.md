# 公开内容检查与保护范围

恢复固件以分区白名单排除设备专属数据，不提供原设备的全片镜像或 QCN。
独立 reference/calibration 目录提供六份经限定范围脱敏的原始分区副本，
仅供参考、不提供刷入方法；处理范围与限制见该目录 README.md。
不附带原备份目录、state.json、SN/IMEI、运行日志或私人路径。

## 已观察到的事实

- EFS2/sys_rev 中能检出原设备序列号，因此不将原样备份复制入仓库；参考副本已对已识别 IMEI/SN/IMSI/ICCID 置无效值。
- usr_data 的用途由启动脚本确认：挂载到 /cache，并承载 /data、/usrdata 等持久化内容；独立参考副本已检查并处理已知身份模式，含压缩内容。
  该副本仍有网络等配置，不构成完整匿名化。
- sec/machine/misc 在原备份中全为 FF；本次独立参考目录原样保留这三个空白区，但不将“本机为空”推广为其他设备可清空。
- 公开九区中未检出已知原设备及记录中其他两台设备的 IMEI/SN。
  检查覆盖 ASCII、UTF-16 和若干 BCD 编码形式；不等于覆盖所有编码和所有未知标识。
- 对已解出的新版 system 文件系统 977 个文件和旧版 recovery 文件系统 877 个文件扫描，
  未检出已知设备身份。旧版 recovery 的结果不能代替新版 recovery 的完整解压审计。
- system 中的 PRIVATE KEY 字符串命中二进制代码/库；仅凭该字符串不能认定存在实际私钥。

## SBL、MIBIB、TZ、RPM

四个文件逐字节哈希符合更新包 compatibility 清单；未发现已知原设备身份。
MIBIB 表头及十五个条目描述分区名、块起点、长度和属性。
已解析的 SBL/TZ/RPM 证书主体为 SecTools/Test CA 类名称，证书序列号为 1 或 5，
可见的 HW_ID/OEM_ID/MODEL_ID 为零；没有观察到按原设备 SN 绑定的证书字段。
这是证书元数据检查，不是完整签名验证，不证明其他镜像均无设备唯一信息。

镜像末尾的连续 FF 填充起点：SBL=223232、MIBIB=6160、TZ=528384、RPM=161792 字节。
非 FF 的前部仍包含程序、头部、签名、对齐等数据；没有把所有非代码字节都解释为个人数据。

## RAWDATA

新旧 RAWDATA 均为四份相同的 128 KiB 块；每块只有第一页有数据，剩余为 FF。
新旧差异集中在型号字符串（Baiwang → EG25G-QDC507）、一个配置字节及四个尾部字节。
没有检出已知设备身份。采用公开更新包原样文件，不采用个人备份的 RAWDATA。
仍有字段未完全解释；不能把“未检出已知标识”表述为绝对匿名性证明。

## 范围保护与发布隔离

默认先核验原更新包的七区哈希，只允许五个精确分区范围，保留其他十区。
仅显式 nand-rebuild 模式允许另外四个底层固件区；六个永久保护区始终不擦写。
修改 XML 不能扩大当前模式的刷写范围。前后对全部未写入分区逐字节比较。若 loader 对坏块映射的语义不同，主机地址检查并不能替代
实机验证，所以没有宣称物理写入已验证安全。

所有备份/日志强制位于仓库外。make_release.py 仅从 PUBLIC_FILES.sha256 显式白名单打包，
不递归打包当前目录，也不含 .git。只允许将明确审核的脱敏参考副本加入公开清单；原样个人备份不得加入白名单或 Git。
